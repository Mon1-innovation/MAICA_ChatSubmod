# Python 2 网络依赖风险

## 位置与版本

仓库在 `game/python-packages/` 中随前端分发并直接导入以下网络库：

| 依赖 | 当前版本 | 主要用途 |
| --- | --- | --- |
| `requests` | 2.27.1 | MAICA HTTP API、节点发现、文件上传下载 |
| `urllib3` | 1.26.9 | `requests` 的连接池、TLS 和 HTTP 传输底层 |
| `websocket-client` | 0.59.0 | MAICA WebSocket 长连接 |

这些版本需要兼容 Ren'Py 所带的 Python 2 环境。Python 2 已于 2020 年终止官方支持，主流网络库的新版本也已停止支持 Python 2，因此无法在保留当前运行范围的同时直接升级到现行安全版本。

## 原因

项目目前仍需支持使用 Python 2 的 MAS/Ren'Py 设备。升级上述依赖通常会引入 Python 3 语法、标准库接口和 TLS 行为要求；单独回移安全修复则需要长期维护私有分支，并持续验证 Windows、Linux、macOS 与 Android 上的 Ren'Py 网络栈，成本和回归风险都较高。

## 影响范围

- 已公开但未回移到这些版本的 HTTP、代理、重定向、证书和 WebSocket 缺陷可能继续存在。
- Python 2 自身的 `ssl`、证书存储和加密套件能力也可能受设备所带运行时限制，不能仅通过替换 Python 包解决。
- vendored 依赖不会自动获得系统包管理器的安全更新。
- 项目会持续承担旧 TLS 服务兼容、代理环境差异和未来服务端协议升级造成的连接风险。

该风险影响所有使用 HTTP API、WebSocket、MVista、MPostal、证书下载或节点发现的联网功能；实际暴露程度取决于设备运行时、所选服务节点及网络环境。

## 后续处理建议

长期方案应以结束 Python 2 支持或隔离 Python 2 联网职责为目标。可评估双运行时构建、受控的兼容分支、外部本地代理/桥接进程、依赖清单与漏洞公告跟踪，以及对官方节点强制现代 TLS。任何短期回移都应针对明确漏洞建立补丁来源、跨平台测试矩阵和发布追踪，而不是无版本约束地替换整个依赖目录。

## 本次处理边界

按本轮审核决定，本次只记录风险，不升级、替换或修补上述网络库，也不改变 Python 2 支持范围。
